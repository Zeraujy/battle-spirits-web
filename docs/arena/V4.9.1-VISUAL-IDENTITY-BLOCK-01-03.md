# v4.9.1 — Arena Visual Identity Alignment
## Steps 01–03: Token Audit, Shared Tokens, Arena Surfaces

### Scope
This block is presentation-only. It does not modify gameplay, online state,
services, HUD composition, contextual actions, targeting rules or card motion.

### Token audit summary
The recent menus already share a stable visual language:
- near-black translucent surfaces;
- white borders between roughly 8% and 24% opacity;
- 12–14px glass blur for elevated chips/panels;
- restrained black shadows;
- 140–180ms interaction transitions;
- white primary text with progressively muted secondary text.

Some of those values were repeated directly across menu CSS rather than exposed
through one shared vocabulary. `interfaceTokens.css` now provides that vocabulary
without rewriting any menu selector in this block.

### Compatibility strategy
`interfaceTokens.css` is additive. Shared tokens alias the already established
`--eternal-*` and global text values where appropriate. Existing menu CSS remains
unchanged, so importing the token file cannot restyle a menu unless a menu opts in
explicitly in a future block.

### First consumers
Only the following Arena surfaces consume the new tokens in this block:
- `ArenaShell`
- `Battlefield`
- `OpponentField` / `CenterField` / `PlayerField` presentation boundaries

### Semantic color isolation
Gameplay-semantic colors remain outside the shared neutral interface tokens.
This includes Core, Soul Core, Battle Spirits symbols, targeting and combat state.

### Acceptance criteria
- Menus render exactly as before this block.
- Arena surface language feels related to the menu without increasing UI density.
- Cards remain visually dominant over the battlefield chrome.
- No gameplay/online files are modified.
- Existing Arena audits remain green.
