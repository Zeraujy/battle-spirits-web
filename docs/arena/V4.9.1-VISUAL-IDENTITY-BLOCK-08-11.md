# v4.9.1 — Arena Visual Identity Alignment — Steps 08–11

## Scope

This block aligns presentation only for:

- `CoreSystemDisplay`
- `HandArea`
- `TargetingUX`
- `ArenaOverlayLayer`
- `GameLogDrawer`
- `GameEventToast`
- `BurstPresentation`

No gameplay, rules, online protocol, reducer, server or service logic is changed.

## Step 08 — Core presentation

Core surfaces now consume the shared interface tokens for surface, border, text, blur, shadow and motion. Gameplay-semantic colors remain local: regular Core presentation keeps blue accents and Soul Core keeps red accents.

## Step 09 — Hand interaction

Hand hover, selection, drag feedback and scrollbar styling now use the shared interaction language. Card art remains the dominant visual element and selection uses a restrained neutral outline instead of a new gameplay color.

## Step 10 — Targeting

Targeting feedback now consumes the shared neutral hierarchy (`border`, `text`, `shadow`, `transition`) while continuing to derive legality entirely from the existing targeting system.

## Step 11 — Overlay surfaces

Log, toast and Burst surfaces now use the shared glass/surface language. Event and Burst colors remain local semantic accents. `ArenaOverlayLayer` pointer behavior is unchanged.

## Safety boundaries

- No files under `src/game`, `src/online`, `src/services`, `server` or `supabase` are modified.
- Core blue and Soul Core red are not moved into global interface tokens.
- Overlay click-through behavior is preserved.
- Existing reduced-motion behavior remains supported.
